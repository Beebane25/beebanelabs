1. Pengenalan Coroutines

Coroutines adalah fitur Kotlin untuk menulis kode asynchronous (non-blocking) dengan cara yang terlihat seperti kode synchronous (sequential). Coroutine jauh lebih ringan dari thread — Anda bisa menjalankan ribuan coroutine tanpa masalah performa.

Masalah utama dengan callback dan thread tradisional:

  • Callback Hell — kode bertingkat yang sulit dibaca
  • Thread berat — setiap thread membutuhkan ~1MB stack memory
  • Kode sulit dipahami — async logic tersebar di berbagai callback

Coroutine menyelesaikan semua masalah ini dengan memungkinkan Anda menulis kode async seolah-olah kode sync.

2. Suspend Function

Suspend function adalah fungsi yang bisa di-pause (suspend) dan di-resume tanpa memblokir thread. Suspend function hanya bisa dipanggil dari dalam coroutine atau suspend function lainnya.

Kotlin — Suspend Function 
import kotlinx.coroutines.*

// Suspend function — bisa di-pause dan di-resume
suspend fun ambilDataPengguna(): String {
    delay(1000L)  // Non-blocking delay (suspend selama 1 detik)
    return "Data Pengguna: Andi, 25 tahun"
}

suspend fun ambilProduk(): List<String> {
    delay(1500L)  // Non-blocking delay selama 1.5 detik
    return listOf("Laptop", "Mouse", "Keyboard")
}

suspend fun kirimNotifikasi(pesan: String): Boolean {
    delay(500L)  // Non-blocking delay selama 500ms
    println("📨 Notifikasi: $pesan")
    return true
}

suspend fun ambilDataDariAPI(url: String): String {
    // Simulasi network request
    delay(2000L)
    return "Response dari $url: {\"status\": \"ok\"}"
}

fun main() = runBlocking {
    println("Mulai...")

    // Memanggil suspend function dari dalam coroutine
    val pengguna = ambilDataPengguna()
    println(pengguna)

    val produk = ambilProduk()
    println("Produk: $produk")

    val sukses = kirimNotifikasi("Data berhasil diambil!")
    println("Notifikasi terkirim: $sukses")

    println("Selesai! 🎉")
}

// Output:
// Mulai...
// Data Pengguna: Andi, 25 tahun
// Produk: [Laptop, Mouse, Keyboard]
// 📨 Notifikasi: Data berhasil diambil!
// Notifikasi terkirim: true
// Selesai! 🎉
⚠️ Penting

Suspend function hanya bisa dipanggil dari coroutine atau dari suspend function lain. Anda tidak bisa memanggil delay() atau suspend function dari fungsi biasa. Gunakan runBlocking di main() untuk membuat coroutine context entry point.

3. Launch

launch adalah coroutine builder yang memulai coroutine baru tanpa mengembalikan nilai (fire and forget). Mengembalikan Job yang bisa digunakan untuk mengontrol coroutine.

Kotlin — Launch 
import kotlinx.coroutines.*

fun main() = runBlocking {

    // ========== Launch — fire and forget ==========
    val job: Job = launch {
        println("Coroutine dimulai di ${Thread.currentThread().name}")
        delay(1000L)
        println("Coroutine selesai! 🎉")
    }

    println("Main thread tetap jalan...")
    println("Menunggu coroutine...")
    job.join()  // Tunggu coroutine selesai
    println("Semua selesai!")

    // ========== Launch dengan nama ==========
    val backgroundJob = launch(Dispatchers.Default + CoroutineName("MyWorker")) {
        println("Worker: ${coroutineContext[CoroutineName]} di ${Thread.currentThread().name}")
        delay(500L)
        println("Worker selesai")
    }
    backgroundJob.join()

    // ========== Multiple launches ==========
    val job1 = launch {
        delay(1000L)
        println("Job 1 selesai")
    }
    val job2 = launch {
        delay(500L)
        println("Job 2 selesai")
    }
    val job3 = launch {
        delay(300L)
        println("Job 3 selesai")
    }
    // Semua berjalan paralel!
    joinAll(job1, job2, job3)  // Tunggu semua selesai
    println("Semua job selesai!")

    // ========== Job hierarchy ==========
    val parentJob = launch {
        println("Parent dimulai")

        val childJob = launch {
            delay(500L)
            println("Child selesai")
        }

        delay(200L)
        println("Parent selesai (tanpa tunggu child)")
        // Parent selesai tapi child tetap jalan
    }
    parentJob.join()  // Tunggu parent + child selesai

    // ========== Cancel job ==========
    val cancelableJob = launch {
        repeat(100) { i ->
            println("Iterasi $i ...")
            delay(100L)
            // Koroutine secara otomatis cek cancellation
        }
    }
    delay(350L)  // Tunggu sebentar
    cancelableJob.cancel("Dibatalkan!")  // Cancel coroutine
    cancelableJob.join()
    println("Coroutine dibatalkan")

    // ========== isActive check ==========
    val longJob = launch {
        var i = 0
        while (isActive) {  // Cek apakah masih aktif
            println("Processing $i...")
            delay(100L)
            i++
        }
        println("Dibatalkan di iterasi $i")
    }
    delay(500L)
    longJob.cancelAndJoin()
    println("Long job dibatalkan")
}

4. Async & Await

async adalah coroutine builder yang memulai coroutine dan mengembalikan Deferred<T> — hasil yang belum tersedia. Gunakan await() untuk mengambil hasilnya.

Kotlin — Async & Await 
import kotlinx.coroutines.*

suspend fun ambilCuaca(kota: String): String {
    delay(1000L)  // Simulasi API call
    return "$kota: ☀️ Cerah, 32°C"
}

suspend fun ambilBerita(): List<String> {
    delay(1500L)  // Simulasi API call
    return listOf("Berita 1", "Berita 2", "Berita 3")
}

suspend fun ambilTrending(): Map<String, Int> {
    delay(800L)  // Simulasi API call
    return mapOf("#Kotlin" to 15000, "#Android" to 12000, "#Compose" to 8000)
}

fun main() = runBlocking {

    // ========== Async — mengembalikan nilai ==========
    val cuacaDeferred: Deferred<String> = async {
        ambilCuaca("Jakarta")
    }
    println("Mengambil data cuaca...")

    val cuaca = cuacaDeferred.await()  // Ambil hasilnya
    println(cuaca)  // Jakarta: ☀️ Cerah, 32°C

    // ========== Multiple Async — paralel ==========
    println("\n--- Mengambil semua data sekaligus ---")
    val startTime = System.currentTimeMillis()

    // Semua berjalan PARALEL
    val cuacaDeferred2 = async { ambilCuaca("Bandung") }
    val beritaDeferred = async { ambilBerita() }
    val trendingDeferred = async { ambilTrending() }

    // Await semua hasil
    val cuaca2 = cuacaDeferred2.await()
    val berita = beritaDeferred.await()
    val trending = trendingDeferred.await()

    val elapsed = System.currentTimeMillis() - startTime
    println(cuaca2)
    println("Berita: $berita")
    println("Trending: $trending")
    println("Waktu: ${elapsed}ms")  // ~1500ms (bukan 3300ms!)
    // Karena semua berjalan paralel, bukan sequential!

    // ========== Sequential vs Paralel ==========
    println("\n--- Sequential (lambat) ---")
    val startSeq = System.currentTimeMillis()
    val c1 = ambilCuaca("Jakarta")       // 1000ms
    val c2 = ambilCuaca("Bandung")       // 1000ms
    val c3 = ambilCuaca("Surabaya")      // 1000ms
    val elapsedSeq = System.currentTimeMillis() - startSeq
    println("Sequential: ${elapsedSeq}ms")  // ~3000ms

    println("\n--- Paralel (cepat) ---")
    val startPar = System.currentTimeMillis()
    val d1 = async { ambilCuaca("Jakarta") }
    val d2 = async { ambilCuaca("Bandung") }
    val d3 = async { ambilCuaca("Surabaya") }
    val results = awaitAll(d1, d2, d3)
    val elapsedPar = System.currentTimeMillis() - startPar
    println("Paralel: ${elapsedPar}ms")     // ~1000ms
    println("Hasil: $results")

    // ========== async dengan supervisorScope ==========
    supervisorScope {
        val job1 = async {
            delay(100L)
            "Sukses 1"
        }
        val job2 = async {
            delay(200L)
            throw RuntimeException("Error di job2!")
            "Sukses 2"  // Tidak pernah tercapai
        }

        try {
            println(job1.await())  // Sukses 1
            println(job2.await())  // Error!
        } catch (e: Exception) {
            println("Error: ${e.message}")
        }
    }
}
💡 Launch vs Async

launch = tidak mengembalikan nilai (fire & forget), mengembalikan Job.
async = mengembalikan nilai, mengembalikan Deferred<T>. Gunakan launch untuk side effects (update UI, logging). Gunakan async untuk mendapatkan hasil (API response, perhitungan).

5. Dispatcher

Dispatcher menentukan thread mana yang akan menjalankan coroutine. Kotlin menyediakan beberapa dispatcher built-in untuk kebutuhan berbeda.

Kotlin — Dispatcher 
import kotlinx.coroutines.*

fun main() = runBlocking {

    // ========== Dispatchers.Default ==========
    // Untuk CPU-intensive work (komputasi berat)
    // Menggunakan thread pool sebanyak jumlah CPU cores
    launch(Dispatchers.Default) {
        println("Default: ${Thread.currentThread().name}")
        // Output: Default: DefaultDispatcher-worker-1

        // Contoh: komputasi berat
        val result = (1..1_000_000).sum()
        println("Sum: $result")
    }

    // ========== Dispatchers.IO ==========
    // Untuk I/O operations (network, file, database)
    // Thread pool yang lebih besar (default 64 thread)
    launch(Dispatchers.IO) {
        println("IO: ${Thread.currentThread().name}")
        // Output: IO: DefaultDispatcher-worker-2

        // Contoh: simulasi I/O
        delay(1000L)  // Simulasi network call
        println("Data dari server")
    }

    // ========== Dispatchers.Main ==========
    // Untuk Android UI thread (hanya tersedia di Android)
    // Tidak bisa digunakan di sini (desktop/JVM biasa)
    // launch(Dispatchers.Main) {
    //     textView.text = "Updated"  // Update UI
    // }

    // ========== Dispatchers.Unconfined ==========
    // Tidak confined ke thread tertentu
    // Berjalan di thread yang memanggilnya, tapi bisa pindah setelah suspend
    launch(Dispatchers.Unconfined) {
        println("Unconfined 1: ${Thread.currentThread().name}")
        delay(100L)
        println("Unconfined 2: ${Thread.currentThread().name}")
        // Bisa berbeda thread setelah suspend!
    }

    // ========== Switch Dispatcher (withContext) ==========
    // Berpindah dispatcher di dalam coroutine
    launch(Dispatchers.Default) {
        println("Mulai di Default: ${Thread.currentThread().name}")

        // Pindah ke IO untuk operasi jaringan
        val data = withContext(Dispatchers.IO) {
            println("Mengambil data di IO: ${Thread.currentThread().name}")
            delay(1000L)  // Simulasi network
            "Data dari API"
        }

        // Kembali ke Default untuk komputasi
        println("Proses di Default: ${Thread.currentThread().name}")
        val processed = data.uppercase()
        println("Hasil: $processed")
    }.join()

    // ========== Custom Dispatcher ==========
    // Thread pool dengan jumlah thread tertentu
    val customDispatcher = Dispatchers.Default.limitedParallelism(2)
    launch(customDispatcher) {
        println("Custom: ${Thread.currentThread().name}")
    }.join()

    // ========== Benchmark: Default vs IO ==========
    println("\n--- Benchmark ---")

    val defaultTime = measureTimeMillis {
        val jobs = (1..100).map {
            launch(Dispatchers.Default) {
                delay(100L)
            }
        }
        jobs.forEach { it.join() }
    }
    println("Default (100 tasks): ${defaultTime}ms")

    val ioTime = measureTimeMillis {
        val jobs = (1..100).map {
            launch(Dispatchers.IO) {
                delay(100L)
            }
        }
        jobs.forEach { it.join() }
    }
    println("IO (100 tasks): ${ioTime}ms")
}

// Helper function untuk mengukur waktu
fun measureTimeMillis(block: suspend () -> Unit): Long = runBlocking {
    val start = System.currentTimeMillis()
    block()
    System.currentTimeMillis() - start
}

Panduan Memilih Dispatcher

Dispatcher Thread Pool Gunakan Untuk
Dispatchers.DefaultWorker threads (CPU cores)Komputasi berat, sorting, parsing
Dispatchers.IOShared pool (max 64)Network, file I/O, database
Dispatchers.MainMain/UI threadUpdate UI di Android
Dispatchers.UnconfinedTidak tetapTesting, logging

6. CoroutineScope

CoroutineScope menentukan lifecycle dari coroutine. Saat scope dibatalkan, semua coroutine di dalamnya juga dibatalkan. Ini sangat penting untuk mencegah memory leak.

Kotlin — CoroutineScope 
import kotlinx.coroutines.*

fun main() = runBlocking {

    // ========== GlobalScope — tidak direkomendasikan ==========
    // Coroutine hidup selama aplikasi hidup (bisa leak!)
    val globalJob = GlobalScope.launch {
        println("GlobalScope: ${Thread.currentThread().name}")
        delay(2000L)
        println("GlobalScope selesai")
    }

    // ========== Custom CoroutineScope ==========
    val myScope = CoroutineScope(Dispatchers.Default + SupervisorJob())

    val job1 = myScope.launch {
        println("MyScope Job1 dimulai")
        delay(1000L)
        println("MyScope Job1 selesai")
    }

    val job2 = myScope.launch {
        println("MyScope Job2 dimulai")
        delay(500L)
        println("MyScope Job2 selesai")
    }

    delay(200L)
    myScope.cancel()  // Batalkan SEMUA coroutine dalam scope
    println("Scope dibatalkan!")
    joinAll(job1, job2)

    // ========== coroutineScope — builder ==========
    // Membuat scope baru dan menunggu semua child selesai
    coroutineScope {
        launch {
            delay(300L)
            println("Child 1")
        }
        launch {
            delay(200L)
            println("Child 2")
        }
        // Menunggu semua child selesai
    }
    println("coroutineScope selesai")

    // ========== supervisorScope ==========
    // Sama seperti coroutineScope, tapi error di satu child
    // TIDAK membatalkan child lainnya
    supervisorScope {
        val jobA = launch {
            delay(100L)
            println("Job A sukses")
        }
        val jobB = launch {
            delay(50L)
            throw RuntimeException("Job B error!")
        }
        jobA.join()
        try {
            jobB.join()
        } catch (e: Exception) {
            println("Job B gagal: ${e.message}")
        }
        println("supervisorScope selesai")
    }

    // ========== Android Lifecycle Scopes ==========
    // Di Android, scope sudah disediakan:
    //
    // viewModelScope — terikat ke ViewModel lifecycle
    // viewModelScope.launch {
    //     val data = repository.fetchData()
    //     _uiState.value = UiState.Success(data)
    // }
    //
    // lifecycleScope — terikat ke Activity/Fragment lifecycle
    // lifecycleScope.launch {
    //     val result = api.getData()
    //     textView.text = result.title
    // }
    //
    // lifecycleScope.launchWhenStarted {
    //     // Hanya berjalan saat lifecycle >= STARTED
    // }
    //
    // repeatOnLifecycle(Lifecycle.State.STARTED) {
    //     // Restart setiap kali lifecycle masuk STARTED
    //     flow.collect { updateUI(it) }
    // }
}

7. Structured Concurrency

Structured Concurrency adalah prinsip bahwa coroutine anak selalu terikat ke coroutine induk. Ketika induk selesai atau dibatalkan, semua anak juga ikut selesai/dibatalkan.

Kotlin — Structured Concurrency 
import kotlinx.coroutines.*

// Service menggunakan structured concurrency
class UserService(private val scope: CoroutineScope) {

    // Menggunakan supervisorScope untuk isolasi error
    suspend fun ambilSemuaData(userId: String): UserData {
        return supervisorScope {
            val profil = async { ambilProfil(userId) }
            val postingan = async { ambilPostingan(userId) }
            val teman = async { ambilTeman(userId) }

            UserData(
                profil = profil.await(),
                postingan = postingan.await(),
                teman = teman.await()
            )
        }
    }

    private suspend fun ambilProfil(id: String): String {
        delay(500L)
        return "Profil $id"
    }

    private suspend fun ambilPostingan(id: String): List<String> {
        delay(800L)
        return listOf("Post 1", "Post 2")
    }

    private suspend fun ambilTeman(id: String): Int {
        delay(300L)
        return 150
    }
}

data class UserData(
    val profil: String,
    val postingan: List<String>,
    val teman: Int
)

// Contoh: Job tree
fun main() = runBlocking {
    println("=== Structured Concurrency ===\n")

    val parentJob = launch {
        println("Parent started")

        val child1 = launch {
            delay(300L)
            println("Child 1 selesai")
        }

        val child2 = launch {
            delay(200L)
            println("Child 2 selesai")
        }

        val child3 = launch {
            delay(100L)
            println("Child 3 selesai")
        }

        // Parent menunggu semua child selesai
        println("Parent menunggu children...")
    }

    parentJob.join()
    println("Parent selesai (termasuk semua children)")

    // Contoh: Cancel propagation
    println("\n=== Cancel Propagation ===\n")

    val parentJob2 = launch {
        val child = launch {
            repeat(100) { i ->
                println("Child iterasi $i")
                delay(100L)
            }
        }

        delay(350L)
        println("Parent membatalkan child")
        child.cancelAndJoin()
        println("Child dibatalkan")
    }
    parentJob2.join()

    // Contoh: Service usage
    println("\n=== Service Usage ===\n")

    val service = UserService(CoroutineScope(Dispatchers.IO))
    val userData = service.ambilSemuaData("user123")
    println(userData)
}

8. Flow

Flow adalah tipe data untuk menghasilkan beberapa nilai secara asynchronous — seperti RxJava Observable atau JavaScript Streams, tapi dengan sintaks yang lebih Kotlin-native.

Kotlin — Flow 
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun main() = runBlocking {

    // ========== Flow Dasar ==========
    val numberFlow: Flow<Int> = flow {
        for (i in 1..5) {
            delay(300L)  // Simulasi delay
            emit(i)      // Menghasilkan nilai
            println("Emitted: $i")
        }
    }

    // Mengumpulkan (collect) flow
    println("--- Collect Flow ---")
    numberFlow.collect { value ->
        println("Received: $value")
    }

    // ========== Flow Builder ==========
    // flowOf — dari nilai-nilai yang sudah diketahui
    val fruitFlow = flowOf("Apel", "Mangga", "Jeruk")
    fruitFlow.collect { println(it) }

    // asFlow — dari collection
    val names = listOf("Andi", "Budi", "Citra")
    names.asFlow().collect { println(it) }

    // ========== Flow Operators ==========
    println("\n--- Operators ---")

    (1..10).asFlow()
        .filter { it % 2 == 0 }        // Hanya genap
        .map { it * it }                // Kuadrat
        .take(3)                        // Ambil 3 pertama
        .collect { println(it) }        // 4, 16, 36

    // ========== Transformasi Flow ==========
    println("\n--- Transform ---")

    (1..5).asFlow()
        .transform { value ->
            emit("Processing $value")
            emit("Result: ${value * value}")
        }
        .collect { println(it) }

    // ========== Terminal Operators ==========
    println("\n--- Terminal Operators ---")

    val sum = (1..100).asFlow()
        .reduce { acc, value -> acc + value }
    println("Sum 1..100: $sum")  // 5050

    val list = (1..5).asFlow().toList()
    println("List: $list")  // [1, 2, 3, 4, 5]

    val first = (1..100).asFlow().first()
    println("First: $first")  // 1

    val count = (1..10).asFlow()
        .filter { it % 2 == 0 }
        .count()
    println("Even count: $count")  // 5

    // ========== Buffer & Conflate ==========
    println("\n--- Buffer ---")

    val slowFlow = flow {
        for (i in 1..5) {
            delay(100L)  // Produksi cepat
            println("Emitting $i")
            emit(i)
        }
    }

    // Tanpa buffer (sequential)
    println("Tanpa buffer:")
    slowFlow.collect { value ->
        delay(200L)  // Konsumsi lambat
        println("  Collected $value")
    }

    // Dengan buffer (paralel)
    println("Dengan buffer:")
    slowFlow
        .buffer()  // Produksi dan konsumsi bisa paralel
        .collect { value ->
            delay(200L)
            println("  Collected $value")
        }

    // Conflate — skip intermediate values jika collector lambat
    println("Dengan conflate:")
    slowFlow
        .conflate()
        .collect { value ->
            delay(300L)
            println("  Conflated $value")
        }

    // ========== Flow Lifecycle ==========
    println("\n--- Lifecycle ---")

    (1..3).asFlow()
        .onStart { println("Flow dimulai") }
        .onEach { println("Value: $it") }
        .onCompletion { cause ->
            if (cause == null) println("Flow selesai tanpa error")
            else println("Flow error: $cause")
        }
        .collect()

    // ========== StateFlow & SharedFlow ==========
    println("\n--- StateFlow ---")

    // StateFlow — selalu memiliki 1 nilai, emit ke semua collector
    val stateFlow = MutableStateFlow(0)

    // Collector di background
    val collectorJob = launch {
        stateFlow.collect { value ->
            if (value > 0) println("StateFlow: $value")
        }
    }

    delay(100L)
    stateFlow.value = 1
    delay(100L)
    stateFlow.value = 2
    delay(100L)
    stateFlow.value = 3
    delay(100L)
    collectorJob.cancel()

    // SharedFlow — emit values ke semua collector
    val sharedFlow = MutableSharedFlow<String>()

    val subscriber1 = launch {
        sharedFlow.collect { println("Subscriber 1: $it") }
    }

    delay(100L)
    sharedFlow.emit("Halo!")
    sharedFlow.emit("Test")
    delay(100L)
    subscriber1.cancel()
}

9. Channel

Channel digunakan untuk komunikasi antar coroutine — seperti queue yang aman untuk concurrent access. Satu coroutine mengirim data (send), coroutine lain menerima (receive).

Kotlin — Channel 
import kotlinx.coroutines.*
import kotlinx.coroutines.channels.*

fun main() = runBlocking {

    // ========== Channel Dasar ==========
    val channel = Channel<Int>()

    // Producer — mengirim data
    launch {
        for (i in 1..5) {
            delay(200L)
            println("Mengirim: $i")
            channel.send(i)
        }
        channel.close()  // Tutup channel setelah selesai
    }

    // Consumer — menerima data
    for (value in channel) {
        println("Menerima: $value")
    }
    println("Channel ditutup")

    // ========== Channel dengan buffer ==========
    println("\n--- Buffered Channel ---")

    val bufferedChannel = Channel<String>(capacity = 3)

    launch {
        val items = listOf("Apel", "Mangga", "Jeruk", "Pisang", "Anggur")
        for (item in items) {
            bufferedChannel.send(item)
            println("Sent: $item")
        }
        bufferedChannel.close()
    }

    for (item in bufferedChannel) {
        delay(500L)  // Consumer lambat
        println("Received: $item")
    }

    // ========== Fan-out — satu producer, banyak consumer ==========
    println("\n--- Fan-out ---")

    val producerChannel = Channel<Int>()

    launch {
        for (i in 1..10) {
            producerChannel.send(i)
        }
        producerChannel.close()
    }

    // Banyak consumer
    val consumers = (1..3).map { id ->
        launch {
            for (value in producerChannel) {
                println("Consumer $id memproses: $value")
                delay(100L)
            }
        }
    }
    consumers.forEach { it.join() }

    // ========== Fan-in — banyak producer, satu consumer ==========
    println("\n--- Fan-in ---")

    val mergedChannel = Channel<String>()

    launch {
        repeat(5) { i ->
            delay(100L)
            mergedChannel.send("Producer A: $i")
        }
    }

    launch {
        repeat(5) { i ->
            delay(150L)
            mergedChannel.send("Producer B: $i")
        }
    }

    repeat(10) {
        println(mergedChannel.receive())
    }
    mergedChannel.close()

    // ========== Channel Patterns ==========
    println("\n--- Produce Pattern ---")

    val numbers = produce {
        for (i in 1..10) {
            send(i)
        }
    }

    // Pipeline: filter genap lalu kuadratkan
    val evenSquared = produce {
        for (value in numbers) {
            if (value % 2 == 0) {
                send(value * value)
            }
        }
    }

    for (result in evenSquared) {
        println("Hasil: $result")  // 4, 16, 36, 64, 100
    }

    // ========== Ticker Channel ==========
    println("\n--- Ticker ---")

    val tickerChannel = ticker(delayMillis = 200, initialDelayMillis = 0)
    repeat(5) {
        tickerChannel.receive()  // Menunggu tick
        println("Tick!")
    }
    tickerChannel.cancel()
}

10. Error Handling

Error handling di coroutine menggunakan try-catch biasa, CoroutineExceptionHandler, dan supervisorScope.

Kotlin — Error Handling 
import kotlinx.coroutines.*

fun main() = runBlocking {

    // ========== try-catch dalam coroutine ==========
    val job = launch {
        try {
            println("Memulai operasi...")
            delay(500L)
            throw RuntimeException("API Error!")
        } catch (e: Exception) {
            println("Error ditangkap: ${e.message}")
            // Log error, retry, atau show fallback
        }
    }
    job.join()

    // ========== CoroutineExceptionHandler ==========
    val handler = CoroutineExceptionHandler { _, exception ->
        println("ExceptionHandler: ${exception.message}")
    }

    val job2 = GlobalScope.launch(handler) {
        throw IllegalStateException("Critical error!")
    }
    job2.join()

    // ========== SupervisorJob — isolasi error ==========
    println("\n--- SupervisorJob ---")

    val supervisor = SupervisorJob()
    val scope = CoroutineScope(Dispatchers.Default + supervisor)

    val child1 = scope.launch {
        delay(300L)
        println("Child 1 sukses ✅")
    }

    val child2 = scope.launch {
        delay(100L)
        throw RuntimeException("Child 2 error! ❌")
    }

    val child3 = scope.launch {
        delay(500L)
        println("Child 3 sukses ✅ (tetap jalan meski child2 error)")
    }

    joinAll(child1, child2, child3)
    println("SupervisorJob selesai")

    // ========== Flow Error Handling ==========
    println("\n--- Flow Error ---")

    val safeFlow = flow {
        emit(1)
        emit(2)
        throw RuntimeException("Error di flow!")
        emit(3)  // Tidak tercapai
    }

    safeFlow
        .catch { e -> println("Flow error: ${e.message}") }
        .collect { value -> println("Value: $value") }

    // ========== Retry pattern ==========
    println("\n--- Retry ---")

    suspend fun <T> retry(
        times: Int = 3,
        delayMs: Long = 1000L,
        block: suspend () -> T
    ): T {
        var lastException: Exception? = null
        repeat(times) { attempt ->
            try {
                return block()
            } catch (e: Exception) {
                lastException = e
                println("Attempt ${attempt + 1} gagal: ${e.message}")
                delay(delayMs)
            }
        }
        throw lastException!!
    }

    var attempts = 0
    try {
        val result = retry(times = 3, delayMs = 500L) {
            attempts++
            if (attempts < 3) throw RuntimeException("Server error")
            "Berhasil setelah $attempts attempts!"
        }
        println(result)
    } catch (e: Exception) {
        println("Gagal setelah semua retry: ${e.message}")
    }
}

11. Best Practices

📋 Best Practices Kotlin Coroutines

✅ DO:

  • Gunakan viewModelScope / lifecycleScope di Android (bukan GlobalScope)
  • Gunakan suspend function untuk operasi async
  • Gunakan withContext(Dispatchers.IO) untuk network/file operations
  • Gunakan supervisorScope untuk isolasi error antar child
  • Gunakan StateFlow / SharedFlow untuk UI state (bukan LiveData)
  • Gunakan flow.catch{} untuk error handling di Flow
  • Gunakan repeatOnLifecycle untuk collect Flow di UI

❌ DON'T:

  • Hindari GlobalScope — bisa menyebabkan memory leak
  • Jangan buat CoroutineScope manual di Android (gunakan yang disediakan)
  • Jangan gunakan Thread.sleep() di coroutine — gunakan delay()
  • Jangan block thread di dalam coroutine — gunakan suspend function
  • Jangan abaikan error — selalu tangkap atau propagate
