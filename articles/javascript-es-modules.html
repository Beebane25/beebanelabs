1. Pengenalan ES Modules

ES Modules (ESM) adalah sistem modul standar yang diperkenalkan di ECMAScript 2015 (ES6) untuk JavaScript. Sebelum ESM, JavaScript tidak memiliki sistem modul bawaan — para pengembang menggunakan pola seperti IIFE, CommonJS (Node.js), atau AMD (RequireJS) untuk memecah kode menjadi modul-modul terpisah.

Dengan ES Modules, setiap file JavaScript secara otomatis menjadi modul dengan scopenya sendiri. Anda bisa mengekspos fungsi, class, atau variabel menggunakan export, dan menggunakannya di file lain menggunakan import.

Mengapa ES Modules Penting?

Keunggulan Penjelasan
Standar ResmiBagian dari spesifikasi ECMAScript, didukung semua browser modern dan Node.js
Module ScopeSetiap file memiliki scope sendiri, tidak ada polusi global
Static AnalysisStruktur import/export dianalisis sebelum kode dijalankan, memungkinkan tree shaking
Lazy LoadingDynamic import memungkinkan loading modul secara asynchronous
Strict ModeESM secara otomatis berjalan dalam strict mode
Dependency GraphBundler dapat membuat graf dependensi yang optimal untuk produksi

Cara Menggunakan ES Modules

Ada beberapa cara untuk mengaktifkan ES Modules tergantung lingkungan:

HTML — Menggunakan ESM di Browser 
<!-- Tambahkan type="module" pada tag script -->
<script type="module" src="./app.js"></script>

<!-- Atau gunakan inline module -->
<script type="module">
  import { fungsi } from './utils.js';
  fungsi();
</script>

<!-- Catatan penting: -->
<!-- 1. Module otomatis deferred (dimuat setelah HTML selesai) -->
<!-- 2. Module berjalan dalam strict mode -->
<!-- 3. Module memiliki CORS policy -->
<!-- 4. Module hanya dieksekusi sekali (cached) -->
JSON — package.json (Node.js) 
{
  "name": "belajar-esm",
  "version": "1.0.0",
  "type": "module",
  "main": "index.js",
  "scripts": {
    "start": "node index.js"
  }
}

// Atau gunakan ekstensi .mjs secara eksplisit
// file: utils.mjs → otomatis dianggap ESM

2. Export: Mengekspos Kode dari Modul

export adalah kata kunci yang digunakan untuk mengekspos fungsi, variabel, class, atau objek dari sebuah modul agar bisa diimpor oleh modul lain. Ada dua jenis export: named export dan default export.

Named Export

Named export memungkinkan Anda mengekspos beberapa nilai dengan nama yang spesifik. Saat mengimpor, nama harus cocok persis (atau di-alias).

JavaScript — mathUtils.js (Named Export) 
// Export saat deklarasi
export const PI = 3.14159;
export const E = 2.71828;

export function tambah(a, b) {
  return a + b;
}

export function kurang(a, b) {
  return a - b;
}

export class Kalkulator {
  constructor() {
    this.hasil = 0;
  }

  tambah(n) {
    this.hasil += n;
    return this;
  }

  kurang(n) {
    this.hasil -= n;
    return this;
  }

  getHasil() {
    return this.hasil;
  }
}
JavaScript — Export di Akhir File 
// Definisi terlebih dahulu, export di akhir
const PI = 3.14159;
const E = 2.71828;

function tambah(a, b) {
  return a + b;
}

function kurang(a, b) {
  return a - b;
}

// Export beberapa sekaligus
export { PI, E, tambah, kurang };

// Export dengan alias (rename)
export { tambah as add, kurang as subtract };

Default Export

Setiap modul hanya boleh memiliki satu default export. Default export tidak memerlukan nama saat diekspor, dan bisa diimpor dengan nama bebas.

JavaScript — Logger.js (Default Export) 
// Default export class
export default class Logger {
  constructor(prefix = 'LOG') {
    this.prefix = prefix;
  }

  info(message) {
    console.log(`[${this.prefix}] INFO: ${message}`);
  }

  warn(message) {
    console.warn(`[${this.prefix}] WARN: ${message}`);
  }

  error(message) {
    console.error(`[${this.prefix}] ERROR: ${message}`);
  }
}

// Juga bisa:
// export default function() { ... }
// export default 42;
// export default { key: 'value' };
⚠️ Peringatan

Jangan mencampur export default dengan export { ... } di baris yang sama dalam cara yang membingungkan. Misalnya, export default const x = 5 adalah sintaks yang tidak valid. Gunakan const x = 5; export default x; sebagai gantinya.

3. Import: Mengimpor Kode dari Modul

import digunakan untuk mengambil nilai yang diekspor dari modul lain. Ada beberapa sintaks import yang bisa digunakan tergantung kebutuhan.

Named Import

JavaScript — Named Import 
// Import spesifik dengan nama yang sama
import { tambah, kurang, PI } from './mathUtils.js';

console.log(tambah(10, 5));   // 15
console.log(kurang(10, 5));   // 5
console.log(PI);               // 3.14159

// Import dengan alias (rename)
import { tambah as add, kurang as subtract } from './mathUtils.js';

console.log(add(10, 5));      // 15
console.log(subtract(10, 5)); // 5

// Import semua sebagai namespace
import * as MathUtils from './mathUtils.js';

console.log(MathUtils.tambah(10, 5));  // 15
console.log(MathUtils.PI);             // 3.14159

Default Import

JavaScript — Default Import 
// Import default — nama bebas
import Logger from './Logger.js';

const log = new Logger('APP');
log.info('Aplikasi dimulai');
// [APP] INFO: Aplikasi dimulai

// Kombinasi default + named import
import Logger, { formatTimestamp } from './Logger.js';

// Atau dengan alias
import MyLogger from './Logger.js';

Import untuk Efek Samping (Side Effects)

JavaScript — Side Effect Import 
// Import hanya untuk menjalankan kode di dalam modul
// Biasanya digunakan untuk polyfill atau inisialisasi global
import './polyfills.js';

// Contoh: polyfills.js
// console.log('Polyfills loaded');
// if (!Array.prototype.at) {
//   Array.prototype.at = function(index) { ... };
// }

Import Assertions dan Import Attributes

JavaScript — Import Attributes (ES2025) 
// Import JSON dengan atribut type
import config from './config.json' with { type: 'json' };
console.log(config.apiUrl);

// Import CSS Module (di bundler seperti Vite)
import styles from './button.module.css' with { type: 'css' };

// Import WebAssembly
import wasmModule from './module.wasm' with { type: 'webassembly' };

4. Re-export dan Barrel Files

Re-export memungkinkan Anda untuk mengimpor nilai dari satu modul dan mengekspornya kembali dari modul lain. Pola ini sangat berguna untuk membuat barrel files — file index.js yang menyederhanakan import dari folder besar.

JavaScript — Re-export Dasar 
// Re-export named exports
export { tambah, kurang, PI } from './mathUtils.js';

// Re-export dengan alias
export { tambah as add, kurang as subtract } from './mathUtils.js';

// Re-export default sebagai named
export { default as Logger } from './Logger.js';

// Re-export semua (kecuali default)
export * from './mathUtils.js';

// Re-export semua termasuk default sebagai namespace
export * as MathUtils from './mathUtils.js';

Barrel File Pattern

File Structure — Barrel Pattern 
src/
├── components/
│   ├── Button.jsx
│   ├── Input.jsx
│   ├── Modal.jsx
│   ├── Card.jsx
│   └── index.js        ← Barrel file
├── utils/
│   ├── format.js
│   ├── validate.js
│   ├── api.js
│   └── index.js        ← Barrel file
└── app.js
JavaScript — components/index.js 
// Barrel file — re-export semua komponen
export { default as Button } from './Button.jsx';
export { default as Input } from './Input.jsx';
export { default as Modal } from './Modal.jsx';
export { default as Card } from './Card.jsx';

// app.js — import menjadi sangat bersih
import { Button, Input, Modal, Card } from './components';

// Tanpa barrel file:
// import Button from './components/Button.jsx';
// import Input from './components/Input.jsx';
// import Modal from './components/Modal.jsx';
// import Card from './components/Card.jsx';
⚠️ Peringatan Barrel Files

Barrel files menyederhanakan import tetapi dapat mempengaruhi tree shaking jika tidak hati-hati. Bundler harus bekerja lebih keras untuk menganalisis re-export. Untuk proyek besar, pertimbangkan import langsung dari file sumber untuk memastikan tree shaking optimal.

Memilih antara default export dan named export adalah keputusan desain yang penting. Masing-masing memiliki kelebihan dan kekurangan.

JavaScript — Perbandingan Penggunaan 
// ✅ Named export — cocok untuk utilitas, constants, helpers
// utils/format.js
export function formatRupiah(angka) {
  return new Intl.NumberFormat('id-ID', {
    style: 'currency',
    currency: 'IDR'
  }).format(angka);
}

export function formatTanggal(date) {
  return new Intl.DateTimeFormat('id-ID').format(date);
}

// ✅ Default export — cocok untuk satu entitas utama per file
// components/UserProfile.jsx
export default function UserProfile({ user }) {
  return (
    <div className="profile">
      <h2>{user.nama}</h2>
      <p>{user.email}</p>
    </div>
  );
}

// ✅ Kombinasi keduanya — file memiliki satu entitas utama + utilitas
// components/Button.jsx
export const VARIANTS = {
  PRIMARY: 'primary',
  SECONDARY: 'secondary',
  DANGER: 'danger',
};

export default function Button({ variant = VARIANTS.PRIMARY, children }) {
  return <button className={`btn btn-${variant}`}>{children}</button>;
}

6. Dynamic Imports

Dynamic imports memungkinkan Anda memuat modul secara asynchronous saat dibutuhkan, bukan saat aplikasi pertama kali dimuat. Ini sangat penting untuk code splitting dan lazy loading.

Sintaks dynamic import menggunakan import() yang mengembalikan Promise.

JavaScript — Dynamic Import Dasar 
// Sintaks dasar — import() mengembalikan Promise
async function loadUtils() {
  try {
    const module = await import('./mathUtils.js');
    console.log(module.tambah(10, 20));  // 30
    console.log(module.PI);               // 3.14159
  } catch (error) {
    console.error('Gagal memuat modul:', error);
  }
}

// Dengan .then()
import('./mathUtils.js')
  .then(module => {
    console.log(module.tambah(10, 20));
  })
  .catch(error => {
    console.error('Gagal memuat modul:', error);
  });

// Destructuring langsung
async function hitung() {
  const { tambah, kurang, PI } = await import('./mathUtils.js');
  console.log(tambah(PI, 10));
}

Conditional (Lazy) Loading

JavaScript — Lazy Loading Kondisional 
// Muat modul hanya jika diperlukan
async function handleFile(file) {
  if (file.type === 'image') {
    const { resizeImage, applyFilter } = await import('./imageProcessor.js');
    const resized = resizeImage(file, { width: 800 });
    return applyFilter(resized, 'grayscale');
  }

  if (file.type === 'pdf') {
    const { parsePDF } = await import('./pdfParser.js');
    return parsePDF(file);
  }

  throw new Error(`Tipe file tidak didukung: ${file.type}`);
}

// Muat library berdasarkan bahasa pengguna
async function formatCurrency(amount) {
  const locale = navigator.language;

  if (locale.startsWith('id')) {
    const { formatRupiah } = await import('./locale/id-ID.js');
    return formatRupiah(amount);
  } else if (locale.startsWith('en')) {
    const { formatUSD } = await import('./locale/en-US.js');
    return formatUSD(amount);
  }

  return amount.toString();
}

Dynamic Import di React (Lazy Loading)

JSX — React Lazy Loading 
import React, { Suspense, lazy } from 'react';

// Lazy load komponen — dimuat saat pertama kali dirender
const Dashboard = lazy(() => import('./pages/Dashboard.jsx'));
const Settings = lazy(() => import('./pages/Settings.jsx'));
const Analytics = lazy(() => import('./pages/Analytics.jsx'));

function App() {
  return (
    <div>
      <nav>
        <a href="/dashboard">Dashboard</a>
        <a href="/settings">Settings</a>
        <a href="/analytics">Analytics</a>
      </nav>

      {/* Suspense menampilkan fallback saat modul dimuat */}
      <Suspense fallback={<div className="loading">Memuat...</div>}>
        <Routes>
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/settings" element={<Settings />} />
          <Route path="/analytics" element={<Analytics />} />
        </Routes>
      </Suspense>
    </div>
  );
}

// Preload modul yang kemungkinan akan dibutuhkan

7. Module Scope dan Hoisting

Setiap file ES Module memiliki module scope sendiri. Variabel, fungsi, dan class yang didefinisikan di dalam modul tidak dapat diakses dari luar kecuali secara eksplisit di-export.

JavaScript — Module Scope 
// utils.js
const SECRET_KEY = 'abc123';        // Private — tidak bisa diakses dari luar
let counter = 0;                     // Private — tidak bisa diakses dari luar

export function increment() {
  counter++;
  return counter;
}

export function getCount() {
  return counter;
}

// app.js
import { increment, getCount } from './utils.js';

console.log(increment()); // 1
console.log(increment()); // 2
console.log(getCount());  // 2
// console.log(counter);  // ❌ ReferenceError
// console.log(SECRET_KEY); // ❌ ReferenceError

Live Bindings

JavaScript — Live Bindings 
// counter.js
export let count = 0;

export function increment() {
  count++;
}

// app.js
import { count, increment } from './counter.js';

console.log(count);  // 0 — ini adalah live binding, bukan copy!

increment();

console.log(count);  // 1 — otomatis ter-update!

// ⚠️ Anda TIDAK bisa mengubah binding dari import
// count = 10;  // ❌ TypeError: read-only

Hoisting dalam ESM

JavaScript — Hoisting 
// ✅ Import di-booisted — bisa ditulis di mana saja dalam file
greet();  // Bisa dipanggil sebelum import statement

import { greet } from './utils.js';

// ❌ Tapi dynamic import TIDAK di-hoist
// await import('./utils.js');  // SyntaxError jika tidak dalam async function

// ✅ Export juga di-hoist
export { myFunction };

function myFunction() {
  return 'Hello!';
}

8. CommonJS vs ES Modules

Di ekosistem Node.js, terdapat dua sistem modul yang berjalan berdampingan: CommonJS (CJS) dan ES Modules (ESM). Memahami perbedaannya penting untuk menghindari error kompatibilitas.

Aspek CommonJS (CJS) ES Modules (ESM)
Sintaksrequire() / module.exportsimport / export
LoadingSynchronousAsynchronous
AnalisisRuntime (dynamic)Static (compile-time)
Tree Shaking❌ Tidak✅ Ya
Ekstensi file.js, .cjs.js (dengan "type":"module"), .mjs
Browser❌ Perlu bundler✅ Didukung native
Top-level await❌ Tidak✅ Ya
__dirname, __filename✅ Tersedia❌ Perlu workaround
JavaScript — Perbandingan Sintaks 
// ═══════════════════════════════════
//           CommonJS (CJS)
// ═══════════════════════════════════

// Export
const tambah = (a, b) => a + b;
module.exports = { tambah };

// Import
const { tambah } = require('./math.js');

// Dynamic require
const modul = require('./' + namaFile + '.js');


// ═══════════════════════════════════
//          ES Modules (ESM)
// ═══════════════════════════════════

// Export
export const tambah = (a, b) => a + b;

// Import
import { tambah } from './math.js';

// Dynamic import
const modul = await import(`./${namaFile}.js`);


// ═══════════════════════════════════
//     Interop: CJS di ESM
// ═══════════════════════════════════

// Import CJS module dari ESM — default export = module.exports
import express from 'express';
import { Router } from 'express';

// ⚠️ Named export dari CJS bisa tricky
// Banyak CJS module hanya punya default export
💡 Tips

Untuk proyek baru, gunakan ES Modules secara konsisten. Jika menggunakan Node.js, tambahkan "type": "module" di package.json atau gunakan ekstensi .mjs. Ini memudahkan tree shaking dan kompatibilitas antara browser dan server.

9. Tree Shaking

Tree shaking adalah teknik optimasi yang dilakukan oleh bundler (Webpack, Rollup, Vite) untuk menghapus kode yang tidak digunakan (dead code) dari bundle produksi. Nama "tree shaking" diinspirasi dari analogi menggoyang pohon sehingga daun-daun yang tidak melekat akan jatuh.

Tree shaking hanya bekerja dengan ES Modules karena strukturnya yang statis — bundler dapat menganalisis dependency graph sebelum kode dijalankan dan menentukan export mana yang benar-benar digunakan.

Cara Kerja Tree Shaking

JavaScript — Tree Shaking dalam Aksi 
// ─── mathUtils.js ───
export function tambah(a, b) {
  return a + b;
}

export function kurang(a, b) {
  return a - b;
}

export function kali(a, b) {
  return a * b;
}

export function bagi(a, b) {
  return a / b;
}

// ─── app.js ───
// Hanya mengimpor `tambah` dan `kurang`
import { tambah, kurang } from './mathUtils.js';

console.log(tambah(5, 3));  // 8
console.log(kurang(5, 3));  // 2
// `kali` dan `bagi` TIDAK diimpor → akan dihapus saat tree shaking

// ─── Hasil bundle produksi (setelah tree shaking) ───
// Hanya tambah dan kurang yang masuk ke bundle
// Fungsi kali() dan bagi() dieliminasi → bundle lebih kecil

Tree Shaking dengan Side Effects

JSON — package.json (sideEffects) 
// package.json
{
  "name": "my-library",
  "sideEffects": false,
  // ↑ Memberitahu bundler: tidak ada file yang punya side effects
  //   sehingga export yang tidak dipakai bisa dihapus

  // Jika beberapa file punya side effects:
  "sideEffects": [
    "*.css",
    "./src/polyfills.js",
    "./src/global-init.js"
  ]
}
JavaScript — Contoh Side Effect yang Perlu Diwaspadai 
// ❌ Side effect — kode ini mempengaruhi state global
// Meskipun export-nya tidak dipakai, kode ini tetap harus dijalankan
export const logger = new Logger();

// Side effect: mengubah window global
window.__APP_VERSION__ = '1.0.0';

// Side effect: mendaftarkan custom element
customElements.define('my-component', MyComponent);

// ✅ Tandai dengan komentar jika perlu
/*#__PURE__*/ tambah(1, 2);

10. Best Practices ES Modules

1. Konsisten Menggunakan Import

JavaScript — Pola Import yang Direkomendasikan 
// ✅ Urutkan import berdasarkan kategori

// 1. Side effect imports
import './global.css';
import './polyfills';

// 2. External library imports
import React from 'react';
import axios from 'axios';
import { format } from 'date-fns';

// 3. Internal absolute imports (dengan alias bundler)
import { apiClient } from '@/services/api';
import { useAuth } from '@/hooks/useAuth';

// 4. Internal relative imports
import { Button } from './components/Button';
import { formatCurrency } from './utils/format';
import type { User } from './types';

// 5. Type-only imports (TypeScript)
import type { Config } from './config';

2. Hindari Circular Dependencies

JavaScript — Circular Dependencies 
// ❌ BURUK: Circular dependency
// a.js
import { fungsiB } from './b.js';
export function fungsiA() { return fungsiB(); }

// b.js
import { fungsiA } from './a.js';
export function fungsiB() { return fungsiA(); }
// → Infinite loop! Runtime error!

// ✅ BAIK: Extract shared code ke modul terpisah
// shared.js
export function fungsiShared() { return 'data'; }

// a.js
import { fungsiShared } from './shared.js';
export function fungsiA() { return fungsiShared(); }

// b.js
import { fungsiShared } from './shared.js';
export function fungsiB() { return fungsiShared(); }

3. Hindari Re-export yang Berlebihan

JavaScript — Re-export yang Optimal 
// ❌ BURUK: Re-export semua dari semua subfolder
// index.js
export * from './components';
export * from './utils';
export * from './hooks';
export * from './services';
// → Sangat sulit untuk tree shaking!

// ✅ BAIK: Barrel file per domain
// components/index.js — hanya komponen UI
export { Button } from './Button';
export { Input } from './Input';

// hooks/index.js — hanya hooks
export { useAuth } from './useAuth';
export { useFetch } from './useFetch';

// Import spesifik ketika membutuhkan optimasi
import { Button } from './components/Button';  // ← langsung

4. Gunakan Path Aliases

JavaScript — vite.config.js (Path Aliases) 
import { defineConfig } from 'vite';
import path from 'path';

export default defineConfig({
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
      '@components': path.resolve(__dirname, './src/components'),
      '@utils': path.resolve(__dirname, './src/utils'),
      '@hooks': path.resolve(__dirname, './src/hooks'),
    },
  },
});

// Sekarang import jauh lebih bersih:
// import { Button } from '@/components/Button';
// import { format } from '@/utils/format';
// import { useAuth } from '@/hooks/useAuth';
💡 Tips Terbaik

Gunakan ESLint dengan plugin eslint-plugin-import untuk mendeteksi masalah import secara otomatis: circular dependencies, unused imports, dan import yang tidak terurut. Konfigurasi rule import/order untuk menertibkan urutan import di seluruh proyek.
